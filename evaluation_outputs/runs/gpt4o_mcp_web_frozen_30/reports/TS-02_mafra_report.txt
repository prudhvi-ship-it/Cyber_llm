Source 3: NIST NVD
Title: CVE-2026-112946: NVD vulnerability record
URL: https://nvd.nist.gov/vuln/detail/CVE-2026-112946
Summary: Vite is a frontend tooling framework for JavaScript. Prior to 6.4.4, 7.3.7, 8.1.6, 8.2.4, and 8.3.3, import analysis can record a root-relative browser URL in safeModulePaths instead of the cleaned resolved module identifier. On a network-accessible, non-Windows development server, an imported project file whose URL matches an absolute host path can authorize a later raw-filesystem request for that host file, provided server.fs.deny does not block it. The request can disclose the matching file outside the project root, but it does not allow arbitrary path traversal because the host path must correspond to a project-relative URL authorized by the application graph. This issue is fixed in versions 6.4.4, 7.3.7, 8.1.6, 8.2.4, and 8.3.3.
Supports: NVD lists CVE-2026-112946 as a research lead; product identity, version applicability, and exploitation remain unverified.

Source 4: NIST NVD
Title: CVE-2026-112950: NVD vulnerability record
URL: https://nvd.nist.gov/vuln/detail/CVE-2026-112950
Summary: Vitest is a Vite-native testing framework for JavaScript and TypeScript projects. From 4.1.11 until 4.1.12 and 5.0.3, isFileLoadingAllowed and the filesystem read interpret backslashes differently on Windows in packages/mocker/src/node/interceptorPlugin.ts. This issue is fixed in versions 4.1.12 and 5.0.3.
