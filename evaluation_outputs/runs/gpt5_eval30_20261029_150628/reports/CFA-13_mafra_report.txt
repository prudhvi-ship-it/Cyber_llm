--- Stream 0 [VALID] ---
Service: SaltStack master (ZeroMQ over TCP 4506; version not visible)

Relevant Events: 172.19.0.1 connected to 172.19.0.2:4506 and initiated a ZeroMQ session consistent with Salt master traffic. The client first probed and then attempted to prepare authentication as root; the server replied with a UserAuthenticationError referencing the root user and an auth blob. Immediately after, the client sent a cleartext runner request invoking salt.cmd to call cmd.exec_code with python3 code that executes a subprocess to touch /tmp/POC on the master. The server then emitted a salt/run event tag with a JID, indicating the runner job was accepted/scheduled.

Malicious Activities: Unauthenticated remote code execution attempt against SaltStack master using the cleartext “runner” path (salt.cmd -> cmd.exec_code with python3, running subprocess to create /tmp/POC). Initial root authentication failed, but the attacker bypassed auth by submitting a cleartext runner request. This aligns with known Salt master unauthenticated runner/wheel exposure.

Attack Success: Succeeded

Evidence: 
- [E-S0000-F000003-001] 172.19.0.1 -> 172.19.0.2:4506 connection to the Salt master service port
- [E-S0000-F000019-003] Server-side “root” user keyword observed during auth handling (UserAuthenticationError)
- [E-S0000-F000019-004] Token-like blob returned with the auth error (likely associated with the failed root auth exchange)
- [E-S0000-F000020-005] Command module indicator (“cmd”) present in client payload, consistent with salt.cmd/cmd.exec_code usage
- [E-S0000-F000004-002] Server responses consistent with job handling; stream payload shows a salt/run JID event tag acknowledging the runner job (job accepted/scheduled)
