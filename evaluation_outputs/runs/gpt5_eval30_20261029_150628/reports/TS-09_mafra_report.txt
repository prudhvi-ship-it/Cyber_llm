Defensive Recommendation:
- Upgrade Apache Tomcat to a fixed release (at least 9.0.99 or later) and keep 9.x fully patched; follow vendor guidance for CVE-2025-24813 and related issues.
- Disable or tightly restrict HTTP PUT/DELETE and DefaultServlet write capabilities unless strictly required; ensure DefaultServlet 'readonly' remains true.
- Disable partial PUT and WebDAV if not required to reduce risk of path-equivalence attacks.
- Avoid file-based session persistence (PersistenceManager with FileStore). If persistence is required, enforce a strict sessionAttributeValueClassNameFilter to whitelist safe classes.
- Segregate and harden upload directories; ensure no public path can influence session storage; block external access to any /sessions-like locations.
- Add WAF/IDS rules and server-side validation to detect/block serialized object signatures (e.g., Commons Collections gadget indicators) and suspicious .session uploads.
- Enforce least-privilege filesystem permissions for the Tomcat process; prevent runtime writes to webroot and sensitive directories.
- Continuously monitor and alert on unusual PUT requests, creation of .session files, and anomalous Cookie usage; retain logs/PCAPs for incident response.
- Audit and minimize deserialization attack surface by removing or updating risky libraries and applying secure coding patterns for object handling.
